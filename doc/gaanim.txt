1. INTRODUCTION                                                 *gaanim-intro*

gaanim.nvim drives the `gaanim` command from Neovim. A project is a folder
with a `gaanim.toml`; a Python file that imports gaanim outside any project is
a project of its own. Several projects can share code, assets and one Python
environment in a workspace (|gaanim-workspace|). The plugin needs no
|setup()|: |:Gaanim| and the |<Plug>| mappings exist once it is on
'runtimepath'.

Requirements: Neovim 0.10+ (0.12 shows exports as progress messages), a
Nerd Font for the default icons (see `icons` in |gaanim-config|) and `gaanim`
on PATH. snacks.nvim is optional and gives the pickers a preview. Run
|:checkhealth| gaanim to see what is found.

                                                                 *gaanim-caps*
The plugin reads `gaanim --help` once and uses what the installed version
offers:
  `--listen`            drive the preview: `preview here` without a restart,
                      |:Gaanim-follow|, |:Gaanim-seek|, play, pause, and the
                      playhead in the code and the statusline
  `--message-format`    exact diagnostic lines and export percent
  `inspect`             |:Gaanim-timeline|, the instant of the cursor's line,
                      stills at the cursor
  names in `export`     stills and ranges of the slide under the cursor
  `project`             workspaces (|gaanim-workspace|): the shared `.venv`
                      and `sys.path` for completion, members, checking and
                      exporting them all
While a preview with `--listen` is open, each `ready` carries the scene's
timeline (the object `inspect --json` prints): the plugin takes it, and after
a save waits for it instead of running the scene again through `inspect`.
Without these the plugin restarts the preview from the cursor's segment and
reads the CLI's text output.

2. COMMANDS                                                  *gaanim-commands*

                                                                     *:Gaanim*
:Gaanim                 Pick a subcommand.

:Gaanim new [slides|video|workspace] [name]                    *:Gaanim-new*
                        Create a project with `gaanim init` in
                        `projects_dir` (or the current directory), with its
                        Python environment, and open its entry script. A
                        name with a path separator is used as a path.
                        `workspace` creates a workspace with `gaanim init
                        workspace` and opens its first member. Inside a
                        workspace, a video or slides project becomes a
                        member of it (|:Gaanim-workspace| `new`); a name
                        starting with `.` or absolute stays a path.

:Gaanim projects                                          *:Gaanim-projects*
                        Pick one of the projects in `projects_dir` and open
                        it. A workspace is one entry, which opens one of its
                        members.

:Gaanim workspace [{action}]                             *:Gaanim-workspace*
                        The workspace of the current file. Actions:
                        `members`   (the default) pick a member and open
                                    it; invalid ones show in red with their
                                    error. The list ends with New video, New
                                    presentation, Check all and Export all.
                        `use [{member}]`
                                    make {member} (a path such as
                                    `videos/intro`) the one shared modules
                                    run as, or pick it.
                        `check [{members}]`
                                    check every member, or those {members}
                                    names (paths or patterns as in
                                    `members`, comma-separated), in one
                                    `gaanim check`. Each member's problems
                                    become its diagnostics, all of them one
                                    quickfix list.
                        `export [{preset}] [{members}]`
                                    export each member, in a process of its
                                    own, to `workspace.output` under the
                                    workspace (`exports/{member}.mp4`: the
                                    files repeat its layout).
                        `new [video|slides] [{name}]`
                                    add a member beside the others of its
                                    kind (a name with `/` is a path from the
                                    workspace) and open it.
                        `info`      what the file belongs to: the members,
                                    the shared folders, the interpreter and
                                    `sys.path`.

:Gaanim preview [here|only]                                *:Gaanim-preview*
                        Open the live preview. It reloads when a project
                        file is saved. `here` moves it to the instant the
                        line under the cursor stands for (the `play` ending
                        there, a stop, a marker, a voiceover's start, a
                        segment's first stop), opening it when it is closed.
                        `only` plays just the segment under the cursor. A
                        failed reload puts the Python error on its line as a
                        diagnostic, and a sign marks the line the preview
                        rests at.

:Gaanim follow [on|off]                                     *:Gaanim-follow*
                        The preview follows the cursor: each line you stop
                        on moves it to that line's instant. Toggles without
                        an argument. The statusline shows the follow icon.

:Gaanim seek {seconds|segment|stop}                           *:Gaanim-seek*
                        Rest the preview at a time, at a segment or Section
                        key (its first stop), or at a named stop.

:Gaanim loop [{segment}|{start} {end}|off]                  *:Gaanim-loop*
                        Loop a slide in the preview, by default the one
                        around the cursor, or a time range: it plays over
                        and over, through its stops, and keeps looping
                        across reloads, so with |gaanim-live| each change
                        shows in the loop. `off` ends it. Needs a Gaanim
                        whose `--listen` takes `loop` (|gaanim-caps|); in the
                        preview window, `L` does the same.

:Gaanim panel                                                *:Gaanim-panel*
                        Toggle a floating playback panel for the preview:
                        the time, a scrubber that seeks where you click, the
                        slides as blocks as long as they last (a click rests
                        the preview at one), and buttons to go back a slide,
                        play or pause, go forward a slide and loop the slide
                        it rests on. In the panel: <Space> plays or pauses,
                        `h` and `l` move a second, `[` and `]` a slide, `L`
                        loops, `q` or <Esc> closes; <Tab> and <CR> reach the
                        buttons from the keyboard. While the preview plays,
                        the time runs on between its reports. Drawn with
                        volt (https://github.com/PaoloLupo/volt, a fork of
                        nvzone/volt with `ui.track`), which it needs.

:Gaanim play                                                  *:Gaanim-play*
:Gaanim pause                                                *:Gaanim-pause*
                        Play the preview from where it rests, or pause it.

:Gaanim present [here] [{duration}] [monitor={n}]          *:Gaanim-present*
                        Present fullscreen with Presenter View. {duration}
                        is the planned length, such as `20m` or `1h30m`.
                        `here` starts at the cursor's line. While you
                        present, the script window follows the slide shown.

:Gaanim stop                                                  *:Gaanim-stop*
                        Close the preview or presentation of the project.

:Gaanim check                                                *:Gaanim-check*
                        Run `gaanim check`. Problems go to the quickfix list
                        and to diagnostics, placed on the script mark,
                        segment or stop they name. Saving a project file
                        runs it in the background (|gaanim-config| `check`).

:Gaanim export [{preset}|{output}] [here] [{options}]       *:Gaanim-export*
                                                               *gaanim-export*
                        Export with a preset, or to {output} whose extension
                        picks the format. `here` limits it to the slide under
                        the cursor. {options} go to `gaanim export`:
                        `--from`, `--to`, `--fps`, `--width`, `--height`,
                        `--quality`, `--transparent`, `--fit`, `--notes`.
                        Presets write to the project's `output_dir`:
                          mp4         MP4, 1080p 60 fps
                          draft       MP4 at 30 fps, fast
                          production  MP4, best encode
                          webm mov gif webp
                          pdf         a page per stop
                          notes       PDF with speaker notes
                          bundle      a .gaanim playback bundle
                          still       one PNG at a marker or time
                        Without arguments, pick a preset.

:Gaanim still [{seconds}|{name}|pick]                        *:Gaanim-still*
                        Export one PNG. Without an argument, the instant the
                        cursor's line stands for, named after it
                        (`talk-question.png`); `pick` asks for a marker or a
                        time.

:Gaanim timeline                                          *:Gaanim-timeline*
                        The timeline `gaanim inspect` reports: segments with
                        their stops, markers and voiceovers, with times.
                        Picking an entry jumps to its line and moves the
                        preview there. It runs the scene, so names built at
                        run time appear too.

:Gaanim outline [{kind}...]                                *:Gaanim-outline*
                        Jump to a segment, section, voiceover, stop or
                        marker of the project, read from the Python without
                        running it. {kind} limits the list. A preview that
                        takes commands moves there too.

:Gaanim script [open|toggle|goto]                           *:Gaanim-script*
                        See |gaanim-script|. Without an argument, toggle.

:Gaanim docs [{text}]                                         *:Gaanim-docs*
                        Search the documentation bundled with the project's
                        Gaanim, which matches the installed version.

:Gaanim api [{name}]                                           *:Gaanim-api*
                        Open the API entry of {name} (default: the word
                        under the cursor). `voiceover` finds
                        `Scene.voiceover`.

:Gaanim log                                                    *:Gaanim-log*
                        Show the output of the gaanim commands run so far.

4. NARRATION SCRIPT                                            *gaanim-script*

Gaanim reads the talk's script from Markdown, by default
`narration/script.md` in the asset directory (or beside the script without
one), or the file given to `scene.narration_script()`. Each `## name` section
is the speaker notes of the segment of that name, ignoring case, or the text
of `scene.voiceover("name")`. A `[stop]`, `[stop name]` or `[stop: name]` line
marks where the speaker advances. `# Title` ends a section, `###` headings are
not read and HTML comments are ignored. Saving it updates the preview.

`:Gaanim script` opens it in a window at the side. While it is open, moving
in the code scrolls it to the section of the slide under the cursor, and to
the mark of the stop the cursor has passed.

`:Gaanim script goto` jumps from a slide's code to its section, adding the
section with a mark per stop when it is missing, and from a section (or a
mark) back to the segment (or stop).

Each section, and each segment in the code, shows how long its text takes to
say at `script.wpm` words per minute, against the segment's `target=`: green
within it, amber up to 15 % over, red beyond. The `# Title` line shows the
whole talk against `scene.slides.target()`. Voiceovers show `● take` once
their recording exists in `narration/`.

5. CONFIGURATION                                               *gaanim-config*

Pass options to `require("gaanim").setup()` or set `vim.g.gaanim` before the
plugin loads. Defaults:
>lua
  {
    cmd = "gaanim",           -- or a list: { "C:/Tools/gaanim/gaanim.exe" }
    projects_dir = nil,       -- e.g. "~/dev/gaanim"
    new = {
      cd = "tcd",             -- "tcd", "cd", "lcd" or false
      git = false,            -- git init new projects
    },
    preview = {
      args = {},              -- extra arguments for every preview
      stop_on_exit = true,    -- close previews when Neovim exits
      editor = true,          -- |gaanim-remote|
      listen = true,          -- drive it with --listen stdio (|gaanim-caps|)
      marker = true,          -- sign on the line the preview rests at
      animating = true,       -- highlight the lines animating while playing
      follow_delay = 120,     -- ms the cursor settles before |:Gaanim-follow|
    },
    present = { duration = nil, monitor = nil },
    check = {
      on_save = true,
      strict = false,         -- --strict: warnings fail too
      debounce = 400,         -- ms after the last save
      quickfix = "errors",    -- open quickfix on "errors", "always", "never"
    },
    export = {
      open = false,           -- open the file when done
      presets = { ... },      -- name = { ext, args?, desc, ask? }
    },
    script = {
      path = nil,             -- script path relative to the project
      wpm = 150,              -- speaking pace for estimates
      follow = true,
      timing = true,
      width = 60,
    },
    outline = {
      patterns = {},          -- { kind = "segment", pattern = "..." }
      ignore = { ".venv", "venv", ".git", "__pycache__", "exports",
                 "snapshots", "node_modules", ".ruff_cache" },
    },
    picker = "auto",          -- "snacks" or "select"
    server = {                -- |gaanim-server|
      enabled = true, hints = true, lens = true, assets = true, typst = true,
    },
    live = {                  -- |gaanim-live|
      delay = 300, while_typing = false, typing_delay = 900, quiet = true,
    },
    icons = "nerd",           -- Nerd Font icons; "unicode" without one, or
                              -- a table overriding some: { segment = "▤" }
    lsp = true,               -- point pyright/basedpyright at the
                              -- project's .venv, where the stubs are
    workspace = {             -- |gaanim-workspace|
      output = "exports/{member}", -- where `workspace export` writes,
                              -- from the workspace's root
    },
  }
<
`outline.patterns` adds Lua patterns whose first capture is a name, for
projects that name slides their own way. For one module per slide with
`NAME = "Cover"`:
>lua
  outline = { patterns = {
    { kind = "segment", pattern = '\nNAME%s*=%s*"([^"]+)"' },
  } }
<

6. STATUSLINE AND EVENTS                                   *gaanim-statusline*

`require("gaanim").status()` returns, or "" outside projects:
  - the slide and stop under the cursor
  - the instant the cursor's line stands for, once |:Gaanim-timeline| (or a
    still at the cursor) has run `gaanim inspect`
  - where the preview rests (`0:01.8 Problem·question`), after the play,
    pause or, while it loops, loop icon (which also marks the signs in the
    code and turns the slide's Loop lens into Unloop),
    or its state while it starts, reloads or failed, and the follow icon
    while it follows the cursor
  - the last check (`✓`, `!n`, `✗`)
Show it only once the plugin has loaded, so the statusline does not load
it: `cond = function() return vim.g.loaded_gaanim == true end`.

                *GaanimCheck* *GaanimPreview* *GaanimPlayhead* *GaanimInspect*
                                             *GaanimWorkspace* *GaanimMember*
|User| events: `GaanimCheck` after each check, with `data.report`;
`GaanimPreview` when the preview's state changes, with `data.root`;
`GaanimPlayhead` when it moves, with `data.playhead` ({time}, {segment},
{stop}, {playing}); `GaanimInspect` when `gaanim inspect` returns;
`GaanimWorkspace` when `gaanim project` answers, with `data.path`;
`GaanimMember` when a workspace's active member changes, with
`data.workspace` and `data.root`.

In a workspace's shared module the statusline shows the active member's
preview and check.

Highlights: `GaanimPlayhead` (the sign) and `GaanimPlayheadText` (the text
after the line), linked to `DiagnosticInfo` and `Comment`.

7. BACK TO THE CODE FROM GAANIM                                *gaanim-remote*

Gaanim opens script lines in the editor `GAANIM_EDITOR` names: the
inspector, the console, a double click on the animation timeline and the
script error panel's "Open in the editor". Previews started from Neovim get
a `GAANIM_EDITOR` that calls this Neovim through its RPC server
(|v:servername|), so those jumps land here. Set `preview.editor = false` to
keep your own `GAANIM_EDITOR`.

8. TYPST MATH COMPLETION                                        *gaanim-typst*

Gaanim reads Typst math in every string passed to `equation(...)`
(`scene.text.equation("x^2 + y")`, without `$`) and in the `$...$` spans of
other text. There, the language server (|gaanim-server|) offers:

  symbols     Typst's math symbols, each with the character it draws as its
              icon. After a `.` it offers the variants of the name before it:
              `arrow.r.` lists `double` (⇒), `long` (⟶)…
  functions   `frac`, `binom`, `sqrt`, `root`, `vec`, `mat`, `cases`, `lr`,
              `abs`, `norm`, `floor`, `ceil`, `attach`, `underbrace`,
              `cancel`, `bold`, `cal`, `bb`… as snippets
  accents     `hat(x)`, `tilde(x)`, `dot(x)`, `arrow(x)`…
  operators   `sin`, `lim`, `log`, `max`…
  spaces      `thin`, `med`, `thick`, `quad`, `wide`

Keyword arguments such as `color="…"`, comments, f-string text and Typst
code after `#` get nothing. The symbol names come from codex 0.3.0, the
version Gaanim's Typst uses; `scripts/gen_typst_symbols.py` regenerates
`lua/gaanim/typst/symbols.lua` from another codex.

Any completion plugin with an LSP source shows them; blink.cmp keeps each
symbol's character as its icon. With `server.enabled = false`, the blink.cmp
source `gaanim.typst.blink` offers the same items:
>lua
  sources = {
    per_filetype = { python = { inherit_defaults = true, "gaanim_typst" } },
    providers = {
      gaanim_typst = { name = "Typst", module = "gaanim.typst.blink" },
    },
  }
<

9. LANGUAGE SERVER                                             *gaanim-server*

A language server written in Lua runs inside Neovim (`vim.lsp.start` with a
function as `cmd`) and attaches, as `gaanim`, to the Python files of Gaanim
projects, next to basedpyright or pyright. It offers:

  inlay hints     the time of each `play`, `stop`, segment, marker and
                  voiceover at the end of its line, from the preview's
                  `ready` or `gaanim inspect` (|gaanim-caps|), refreshed
                  after each save; hidden while
                  the buffer has unsaved changes
  code lenses     over each slide: Preview, Loop, Still, its script's
                  spoken time against `target=` (or Write script), its
                  time; over each voiceover: whether its take is recorded.
                  Run one with `grx` (Neovim 0.12) or
                  |vim.lsp.codelens.run()|
  hover           what the line makes on the timeline; on an asset name, the
                  file's size and, through ffprobe, its pixels or length
  code actions    write a slide's or voiceover's missing script, name an
                  unnamed stop, add a marker below, preview the line, export
                  its frame or its slide as a draft
  symbols         slides with their stops, markers and voiceovers
  completion      asset names inside `image`, `svg`, `audio`, `sfx`, `sound`,
                  `video`, `lottie`, `gltf`, `narration_script` and
                  `preload`; Typst math (|gaanim-typst|)
  diagnostics     asset names that resolve to no file

Turn parts off with `server` in |gaanim-config|. Inlay hints follow
|vim.lsp.inlay_hint.enable()|; the plugin enables them and code lenses for
the buffers it attaches to.

10. LIVE MODE AND NUDGES                                         *gaanim-live*

                                                                *:Gaanim-live*
:Gaanim live [on|off]   In live mode a changed project file is written
                        `live.delay` ms after you stop changing it in normal
                        mode (and while typing when `live.while_typing` is
                        on), without write autocommands such as formatters.
                        Gaanim reloads on each write, so the preview shows
                        the change at once; failed reloads only update the
                        diagnostics (`live.quiet`). Turning it on opens the
                        preview at the cursor when it is closed.

While the preview plays, the lines whose `play` is animating are highlighted
(`GaanimPlaying`, linked to `LspReferenceText`); `preview.animating` turns
it off.

                                                     *<Plug>(gaanim-nudge-up)*
                                                   *<Plug>(gaanim-nudge-down)*
Like CTRL-A and CTRL-X, for decimals too: the number at or after the cursor
moves by its own precision times the count (`0.8` → `0.9`, `0.25` → `0.26`,
`3` → `4`). Outside Gaanim projects they are CTRL-A and CTRL-X.

11. COLORSCHEME                                           *gaanim-colorscheme*

`:colorscheme gaanim` follows 'background'; `gaanim-light` and `gaanim-dark`
set it. The colors are Gaanim's: violet keywords, gold types and titles,
mist borders, on warm paper or graphite. Every text color reads at 4.5:1
(WCAG AA) or more on the background, the cursor line, floats and the
selection; line numbers at 3:1. The groups cover the editor, Treesitter, LSP
semantic tokens, diagnostics, |lsp-inlay_hint| (`LspInlayHint`), code
lenses, the plugin's own groups and LazyVim's plugins. lualine's `auto`
theme finds `lualine.themes.gaanim`.

                                                        *gaanim.theme.setup()*
Options go to `require("gaanim.theme").setup()` before the colorscheme
loads: >lua
    require("gaanim.theme").setup({
      transparent = false,   -- no editor or float background
      italic = true,         -- comments, builtins, parameters
      on_colors = function(colors, variant) end,
      on_highlights = function(groups, colors, variant) end,
    })
<
`on_colors` changes the palette (`lua/gaanim/theme/palette.lua`) and
`on_highlights` the groups before they are set.

12. WORKSPACES                                              *gaanim-workspace*

A workspace is several Gaanim projects in one repository that share Python
code, assets and one Python environment. A `[workspace]` table in the root
`gaanim.toml` lists its members; `[workspace.shared]` names the shared
folders (`src` and `assets` by default, when they exist):
>toml
  [workspace]
  members = [{ path = "season-1/*", group = "Season 1" }, "trailer"]

  [workspace.shared]
  python = ["common"]
<
The plugin asks `gaanim project <file> --json` (|gaanim-caps|), in the
background and without running Python, what each file belongs to: its
project, its workspace and members, the folders its scripts find on
`sys.path` and the interpreter. It keeps the answers until a `gaanim.toml`
is written.

Completion ~
pyright and basedpyright get the interpreter of the workspace's `.venv` (or
the member's own, when it has one) as `python.pythonPath`, and the folders
of `sys.path` added to `analysis.extraPaths` (`basedpyright.analysis` for
basedpyright), after the ones already there: the shared Python, the
member's `src/` and folder, the workspace root. Folders only get added, so
one client serves every member opened.

Active member ~
The workspace's own files, a shared module above all, run as part of a
member: the one whose files were entered last. From a shared module,
|:Gaanim-preview|, |:Gaanim-check|, |:Gaanim-live|, |:Gaanim-follow| and
the times in the code work with that member; saving one marks every
member's timeline stale, as the module is part of each scene. With no
member entered yet, a command takes the only member, or asks which one and
runs again with it; `:Gaanim workspace use` changes it. A script that
imports gaanim outside the shared Python folders (a sketch at the root) is
a project of its own.

Assets ~
Names that are not in the member's folders are looked up in the shared
asset folders, as Gaanim does: completion offers them (marked `shared`) and
they are not reported missing.

Members ~
|:Gaanim-workspace| lists, checks, exports and adds members. A member whose
`gaanim.toml` is invalid shows in red with its error, and checking the
workspace reports it on its manifest.
